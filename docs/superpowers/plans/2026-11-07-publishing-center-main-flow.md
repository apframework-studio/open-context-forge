# 发布中心主流程续建

## 范围

沿已验收的发布中心原型继续完成可操作闭环：文章定稿后分别准备微博、即刻稿；共享素材支持上传和基于文章的真实生成；人工发布后记录渠道结果。平台直发需要单独的连接方式与凭据，不在这轮伪装为已接入。

## 实施顺序

1. 图像服务：本机保存 Gemini API Key（仅返回是否配置），列出稳定图片模型；以文章标题、摘要、正文片段与用户提示词调用官方 Interactions 图片接口。无 Key、无效参数、服务失败均不写素材。
2. 生成素材：把成功结果保存为文章素材，记录模型、提示词、源修订和画幅；沿用现有图片选择、排序、删除和跨渠道引用。
3. 发布交接：微博、即刻各自提供文案复制、图片逐张下载、外部平台入口，以及手动登记发布时间和链接。发布记录独立于渠道稿；稿件再次修改或源文章变化后显示需重新准备。
4. 浏览器验收：在 1440×810 验证定稿、配置、生成、共享、渠道准备和人工发布记录；在窄屏验证关键操作不丢失。使用假的图片服务做自动化测试，不消耗实际 API 配额。

## 数据与安全

- Key 存在本机受限文件中，API 只返回配置状态；不写入浏览器本地存储或响应体。
- 图片生成必须由用户点击触发，服务端白名单限定模型和画幅。文章上下文只在触发时发送给 Gemini。
- 生成失败不产生素材或渠道引用。外部发布动作由用户在平台完成，本机只记录用户确认的结果。
