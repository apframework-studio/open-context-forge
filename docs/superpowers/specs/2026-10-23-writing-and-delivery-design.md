# 多文章写作与渠道任务设计

## 已落地的文章工作台

“新建文章”立即创建空白项目，不要求先填写标题、公开摘要、发布日期，也不要求先选来源。创建后可直接写正文并使用该文章独立的主对话；标题随时补充，公开摘要和发布日期收在“发布信息”中，定稿时才必填。未关联来源的对话会明确提示缺少证据，不能把想法当作来源事实。

左侧列表可搜索、按状态筛选并切换文章；切换前保存未提交的编辑。状态由服务端按当前文章修订和发布记录计算：**新建**为空白草稿，**写作中**为有正文的草稿，**已完成**为已定稿但尚无当前修订的发布包，**待发布**为当前修订已有发布包或正待公开验证，**已发布**为公开链接已验证。新修订会回到“写作中”；旧修订的发布记录不会让新修订显示成已发布。

浏览器只保存上次选中的文章 ID；文章内容、修订、状态和对话保存在本机服务中。没有上次选中记录时，工作台显示列表和空白引导，不自动打开某篇旧文章。

## 决策

文章是稳定的工作单元；每篇文章默认有一条主对话。对话、草稿、证据选择和任务都绑定文章 ID，不使用全站共享长对话。切换文章时恢复该文章的编辑状态及对话。一个文章可以在以后增加“资料研究”“提纲”“审稿”等子对话，但首版先保留现有的主对话；切换智能体方案时，当前实现按 `(articleId, profileId)` 保留独立会话。

2026-10-24 调整：资料分析卡是资料页的可重跑辅助结果，状态只有“未分析／已分析”，不需人工确认，也不作为文章写作的前置输入。文章仍可引用来源快照；多来源证据选择需在文章工作台另行设计。智能体可提出提纲、段落和修订建议，正文变更仍由文章修订 API 保存。对话文本不承担任务状态或文章正文的权威记录。

## 工作台界面

- 左侧文章列表显示标题、状态、最近修改时间、来源数和下一条渠道任务时间；可创建、搜索、切换多篇文章。
- 中间按“资料与证据 → 提纲 → 草稿 → 审稿 → 定稿”展示编辑区。一次只编辑一篇，保存按文章修订号检查冲突；后台任务在其他文章运行不覆盖当前草稿。
- 右侧显示当前文章主对话及任务结果。每个智能体执行产生明确的提案与来源引用，用户可接受或拒绝；不同文章的上下文、会话 ID 与输出不混用。
- 文章列表的运行状态独立显示。首版每篇文章同时至多一项写作任务，整个本机服务至多两项模型任务；队列持久化，失败可单项重试。

## 渠道任务

任务记录 `articleId`、已定稿 `revision`、正文及资源哈希、渠道、发布包 ID、预约时间（UTC）与用户时区、授权时间、状态和幂等键。设置任务前先看本地预览及渠道包，并一次性确认“到点自动发布”。文章任何新修订、渠道包变化或渠道配置变化都会暂停任务，要求重新预览和授权。

apframework 博客首版由本机 Fastify 服务持久化调度：服务运行时到点执行，启动时扫描过期任务并按用户选择的“错过时间策略”处理。执行前重新核对定稿修订、哈希、渠道包和配置；提交后单独验证公开页面，只有验证成功才标记 `live`。失败保留错误与尝试记录，重试使用同一幂等键，避免重复文章。

本机关机或服务停止时不会触发任务；界面显示此限制和下一次运行状态。SaaS 版可复用任务与渠道接口，把执行器迁到云端，并增加租户隔离、凭据管理与审计。

公众号先做独立渠道包和人工发布记录。自动提交或群发需核对账号权限、接口能力及审核流程后单独设计；不能把“生成公众号草稿”标成“已推送”。

## 分期任务

1. **来源分析卡**：`article-reader` 只读分析来源，证据逐条定位到快照行号；完成后在资料页显示结果，可重新分析。
2. **多文章工作台**：文章列表、切换、创建、独立自动保存；主对话随文章切换；恢复上次文章。
3. **证据写作**：一篇文章引用多份来源快照，选择证据并生成提纲/草稿提案，人工接受后保存新修订；资料页分析卡不直接充当文章输入。
4. **博客定时任务**：定稿预览、任务授权、持久化调度、版本失效、执行与公开链接验证。
5. **公众号渠道**：先完成人工发布包；自动化能力以账号与官方接口实测结果确定。

## 各期验收点与数据契约

| 阶段 | 可验收结果 | 核心持久数据 |
| --- | --- | --- |
| 1 来源卡 | 分析作为后台任务接受单篇或批量提交；切换页面后任务继续，服务重启后恢复未完成任务；完成后从资料页打开分析卡；证据能定位快照行；状态为未分析或已分析，可重新分析，失败保留上一版卡片 | `analysis_jobs` 保存任务状态，`capture_analyses` 保存新生成的卡片；历史 `source_analyses` 和分析文件继续可读 |
| 2 多文章 | 同时创建至少三篇、来回切换时各自草稿和主对话保持独立；关闭浏览器再打开仍可从列表进入 | 文章项目文件 + `articles` 索引中的标题、修改时间；对话继续按文章 ID 保存 |
| 3 证据写作 | 一篇文章可选两份及以上来源快照，生成提纲和草稿提案；接受提案才增加修订号 | `article_sources(article_id, vault_id, fingerprint, selected_evidence)` 与文章版本文件 |
| 4 博客预约 | 指定时区时间与已定稿修订预约；服务持续运行时到点提交；正文再改、配置变化或错过时间会暂停；公开链接验证后才显示成功 | `publication_jobs` 与 `publication_attempts`，记录修订、哈希、渠道包、UTC 时间、时区、授权和幂等键 |
| 5 公众号 | 生成并预览渠道包，人工发布后记录链接与时间；自动接口单独验证后再增执行器 | 渠道包、人工发布记录；不复用博客的“live”推断 |

文章列表和任务列表都从服务端读取；浏览器 localStorage 只记住上次选中的文章 ID。模型运行状态、发布状态和失败原因由服务端持久化，页面刷新后可恢复。首版不允许模型在分析或写作任务中直接执行发布动作。

## 待确认的产品细节

- 预约时间已错过而本机随后启动时：默认暂停并提醒重新确认，避免在非预期时刻公开。
- 多篇文章引用相同来源卡时只维护一份卡；文章保留引用的来源指纹，方便在来源更新后识别证据过期。
