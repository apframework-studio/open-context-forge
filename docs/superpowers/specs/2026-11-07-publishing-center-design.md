# 发布中心第一阶段设计

## 目标

把已定稿文章集中到发布中心，让用户为微博、即刻分别准备和保存渠道稿，并在一篇文章内上传、复用和删除图片。浏览器以 16:9 横屏为主，同时适配窄屏。博客保留现有发布流程，暂不并入新的渠道稿编辑器。

## 页面与流程

1. 发布中心从文章列表读取 `status=final` 的文章。渠道列由服务端返回的渠道目录生成。当前目录包含微博、即刻；未计划、草稿、待发布、文章有新修订分别展示。
2. 点击文章进入发布准备页。用户选择微博或即刻，首次进入时创建该渠道稿。微博有正文和话题；即刻有正文和讨论引导。每篇文章、每个渠道各有一份可保存的稿件。
3. 图片素材按文章保存到本机。用户上传 PNG、JPEG、WebP；同一素材可同时加入两个渠道稿，各渠道独立排序。删除时先列出引用渠道，确认后从未发布稿中移除引用并删除素材文件。现有博客已发布包中的图片副本不受影响。
4. 渠道稿记录所依据的文章修订号。文章重新定稿后，渠道稿显示“文章有新修订”；用户主动确认同步，保留渠道文案和图片选择。
5. 图片制作工作区展示文章标题、摘要、修订号和提示词。首阶段保留模型与 Key 配置入口，未配置有效 Key 时禁用真实生成。真实生成接入为下一阶段，不伪装成已生成图片。

## 数据边界

- `publish_channel_drafts`：文章 ID、渠道 ID、源修订、渠道内容、准备状态、更新时间。是否计划某渠道由是否存在渠道稿表达。
- `publish_media_assets`：文章 ID、图组、名称、MIME、文件扩展名、来源、创建时间。图片文件放在文章项目目录的 `publish-assets/` 下，随文章永久删除一并清理。
- `publish_channel_images`：渠道稿与图片的多对多关系及顺序。删除图片在一个事务中移除关系和元数据，再删除磁盘文件。
- 图像生成的提示词、模型、源修订等元数据待真实生成接入时存入素材记录。渠道连接方式与渠道内容保持独立。

## 接口与错误

- `GET /api/v1/publish-center` 返回已定稿文章与动态渠道目录、各渠道状态。
- `GET/PUT /api/v1/articles/:id/channel-drafts/:channel` 读取、创建和保存渠道稿；`POST .../sync` 主动同步源修订。
- `GET/POST /api/v1/articles/:id/publish-assets` 列出与上传素材；`GET .../:assetId/file` 预览文件；`DELETE .../:assetId` 删除并返回受影响渠道。
- 写入要求文章仍为定稿；无效渠道、超大文件、非法图片类型和跨文章图片引用返回明确错误。外部发布动作不在本阶段。

## 验收

- 刷新后渠道稿、状态、图片与顺序仍在；一张图片可在微博和即刻共用。
- 删除被引用图片前能看到影响，确认后两个稿件的引用和本机文件同步清除。
- 文章新修订不会自动覆盖渠道文案；主动同步后过期提示消失。
- 无 Key 时不能触发真实图片生成。16:9 横屏完成全流程，窄屏不丢失操作。
