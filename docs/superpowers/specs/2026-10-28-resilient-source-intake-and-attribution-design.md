# 可靠资料入库、知识维护与来源归属设计

日期：2026-10-28
状态：用户于 2026-10-29 确认，进入实施

## 背景与已确认决定

产品主线是资料进入平台、入选定知识库，再由用户手动选取 1–N 份资料写文章，最后确认发布到 Blog。本设计只调整资料进入知识库及其后续知识维护；文章选材、写作和发布流程保持现状。

当前 `import_items` 持久保存接收记录；自动入库由服务启动或上传后扫描 `ready` 项并逐条调用 `fileCapture`。知识维护由 SQLite 中的 `analysis_jobs` 串行调用 Claude CLI。原文入库脚本限时 60 秒，Claude 阶段限时 10 分钟，但任务没有持续的执行期限与可恢复租约；Claude 超时仅发送终止信号，尚未确认进程退出就可能开始下一任务。资料页轮询维护状态，其他页面没有待处理入口或隔日提醒。`ask_user` 与普通跳过同属 `skipped`，不利于提醒用户。

本地文件解析目前只取标题，未读取 frontmatter、HTML 元数据或明确署名；入库时本地文件统一记为 `unknown`，带 URL 的来源统一记为 `third_party`。vault-maintainer 已接受 `--author`、`--authorship`，并禁止仅凭文件路径或 URL 推断归属。用户确认：**归属由导入规则设置默认值，单篇可改；作者尽量从文章明确署名中提取。**

## 目标与边界

1. 资料被接收后立即留下持久记录；目标 vault 已确定时自动排队，接收请求不等待入库或智能体完成。
2. 一个资料或一个 CLI 卡住时，其他可执行资料继续推进；同一时刻最多一个来源分析／知识编译 Claude CLI 进程。
3. 可安全重试的失败自动延时重试；不确定的文件写入、归属冲突及用户判断进入人工待处理。未解决事项可在以后打开界面时提醒。
4. 重复推送同一来源到同一 vault 不重复创建 raw 快照或知识维护任务。一个来源进入不同 vault 时仍分别处理。
5. 从可靠的文章元数据提取作者，单独记录作者与原文归属；用户可以在入库前单篇修改，并在入库后受控纠正。

不包括浏览器插件接入、自动写文章、改变 1–N 手动选材、自动发布、外网查找作者、跨 vault 合并知识或系统通知。应用关闭期间不发送提醒；下次打开界面时展示未解决事项。

## 方案选择

**采用增量双阶段队列。** 接收与 raw 入库继续依托 `import_items`，增加每个目标 vault 一条持久 `filing_jobs`；知识分析与编译扩展现有 `analysis_jobs`。raw 入库使用短时 Node 脚本执行位，来源分析和编译继续共享唯一 Claude CLI 执行位。两个阶段通过已验证的 `import_item_vaults` 关联衔接。

未采用把 raw、维护、文章写作全部放进一个队列：长时间的 Claude 分析会延误后续资料的 raw 入库。也未引入通用工作流框架或仅靠定时扫描重启进程；现有 SQLite 状态足以表达这条主线，显式任务状态更容易恢复和检查。

```text
资料到达 → import_item 持久化
  → 已选目标 vault：filing_job 排队 → raw 快照与 manifest 校验 → import_item_vaults
  → 该 vault 已启用自动维护：analysis_job 排队
      → 分析 → 查重与计划 → 草拟笔记 → 受控写入与校验
      → 已完成 / 正常跳过 / 待人工处理
```

手动入库及向第二个 vault 追加，也只创建 `filing_job`，不在 HTTP 请求中等待脚本。没有目标 vault 的资料留在“待整理”，用户选择目标后进入同一队列。新安装默认选择内置默认 vault 并启用自动入库；升级现有安装时保留已存的 `manual` 或 `auto-file` 规则，不静默改动。每个 vault 的“入库后自动维护”开关仍独立且默认关闭；关闭后不再新增维护任务，已运行任务继续安全完成，排队任务可由用户取消。

## 状态、数据与幂等性

`filing_jobs` 以 `(batch_id, capture_id, vault_id)` 唯一，保存 `queued/running/retry_wait/completed/needs_attention/cancelled`、阶段、尝试次数、`run_token`、开始时间、执行期限、下次重试时间、错误码和结果快照。`analysis_jobs` 保留现有 ID 与结果，增加同类的运行与重试字段；区分 `skipped` 的正常结论 `defer`、`keep_raw_only` 和需要用户动作的 `ask_user`，后者进入 `needs_attention`。旧记录迁移时不重跑已完成任务；历史 `skipped + ask_user` 迁为待处理事项。

`import_items.status` 仍表示资料的整体摄入情况；每个 vault 的入库与维护进度以任务和 `import_item_vaults` 为准，避免一份资料已进入 A 库时掩盖 B 库仍在排队。入库成功后，在同一 SQLite 事务内写入 membership、稳定来源映射和有条件的维护任务，再唤醒维护 worker。文件系统与 SQLite 无法组成单一事务；服务重启时必须先检查快照、manifest 和指纹，再补齐缺失的数据库关联或进入待处理。

raw 指纹是**文件字节哈希**，不充当重复推送标识。本地文件的 raw 包装含每次导入时间，直接按 raw 指纹去重会重复分析。新增稳定 `source_key = SHA256(来源类型 + NUL + 来源位置 + NUL + 原文 contentHash)`：本地来源位置是 Unicode NFC、斜杠统一后的相对文件名；Clipper 来源位置是 URL 解析器规范化并移除 fragment 后的原始 URL，保留 query，不猜测跟踪参数。新表 `vault_source_keys` 以 `(vault_id, source_key)` 唯一，指向已验证的 snapshot/fingerprint。相同键重复推送时新增接收记录，但复用现有快照及维护任务状态；已失败或待处理的任务不因重复推送而自动重跑，仍由重试入口处理。若已知作者或归属冲突，停止元数据合并并列为待处理，不静默覆盖。不同文件名或 URL 即使正文相同也保留独立来源身份。迁移时从已有记录建立映射；历史同键多快照选择最早且哈希验证通过的一份作为后续复用对象，保留其他历史文件与记录，不自动删除或重编译。

## 阻塞处理与恢复

- Worker 每次领取任务时写 `run_token`、开始时间与阶段执行期限，并持续续约 worker 租约。续约仅代表服务存活，不伪装成 CLI 有内容进展；界面显示真实阶段和已运行时间，不展示虚构的进度百分比。
- raw 入库阶段保留 60 秒上限；Claude 的每个分析、计划、草拟阶段保留 10 分钟上限。超时或取消先请求终止，等待退出；宽限期后强制终止并再次确认退出。确认前不释放该执行位，保持单 CLI 串行约束。若强制终止后进程仍无法退出，暂停该执行位并显示全局人工处理事项；独立的 raw 入库执行位仍可继续。
- 安全的只读分析／计划失败最多自动重试两次，分别延后 1 分钟和 10 分钟；等待期间执行其他就绪任务。超限后转人工待处理。CLI 未安装或未登录时暂停 Claude 执行位并生成一条全局待处理事项，不逐条耗尽任务尝试次数；环境恢复或人工点击“继续”后重排。
- raw 入库超时后先核对 manifest、快照和锁文件。完全落盘则补齐 membership；能证明未写入时可重试；留下不明快照或锁时进入待处理，不自动删除锁。知识笔记写入阶段中断时依据现有 journal、目标哈希及校验结果判定完成、可回滚或需检查；无法证明安全时不自动重试。
- 服务重启时检查过期租约。分析／计划阶段可重新排队；raw 与 wiki 写入阶段先做文件对账。单篇失败、延时重试或待处理不阻塞其他可执行任务；同 vault 的写入仍遵守锁与文件哈希检查。

## 作者、归属与修正

导入器在生成 raw 前提取作者，并保存值、依据类型、原文位置和是否被用户覆盖。优先级为 Clipper 的结构化 `source.author`、Markdown frontmatter 明确 `author/authors`、HTML `meta` 或 JSON-LD 作者、正文标题附近明确的“作者／撰文／By”署名。HTML 作者元数据要在移除 `<head>` 前读取。多个明确作者按原文顺序以分号连接为当前 `author` 字符串；名称不完整、多个来源冲突或仅从文件名／站点域名猜测的值只作为候选，不自动写入 manifest。抽取使用有界确定性解析，不另启一个大模型任务。

`author` 表示文章署名；`authorship` 表示是否为用户本人作品，两者独立。扩展导入规则保存 `defaultAuthorship=self|third_party|unknown`，初始值为 `unknown`；上传时可覆盖本批默认值，单篇修正优先于规则默认值。资料已被 worker 领取时，修正通过下述受控补正流程生效。Clipper URL、本地文件类型和署名本身均不自动推断 `third_party`。`unknown` 可正常进入分析；只有真实归属冲突或该知识判断必须由用户决定时，任务才进入待处理。入库时把确定的作者及归属传给现有 maintainer 参数，raw 中保留原始文章署名；推断出的作者不再额外写入可能过时的合成 raw 头部。

资料详情提供“修正来源信息”。对尚未入库项，修改接收记录及待领取任务；运行中的任务冻结本次元数据，修改在下一次受控修正中执行。对已入库项，先核对当前 manifest 值、快照和用户提交的预期版本，再通过受控元数据更新操作修改 manifest，保留 raw 字节与历史变更记录。现有 `import-markdown.js` 可补全 `unknown` 或空作者；已知值的纠错需在相邻 vault-maintainer 仓库新增带预期旧值和审计记录的受控 CLI 命令，不能绕过其冲突保护静默覆盖。若已编译知识笔记包含旧归属或作者，则排入定向元数据同步与校验；无法安全同步时显示待处理，不把不一致的笔记标记完成。**现有 SKILL.md 的归属规则无需修改。**

## 界面与 API

- “资料与分析”对每个目标 vault 展示 raw 入库和知识维护两段状态、当前阶段、已运行时间、错误原因与下一次自动重试时间。正常跳过显示决定及计划；`ask_user` 显示明确的待判断事项。
- 全局导航显示未解决待处理数量。进入应用时读取 SQLite 中的待处理列表；事项超过 24 小时未解决时显示一次横幅，此后每个本地日历日最多提醒一次。用户关闭横幅不关闭事项；处理完成后才从计数中移除。应用关闭期间不发送系统通知。
- 待处理列表支持查看来源、vault、错误码、分析卡、计划、journal 与目标路径；根据阶段提供“重试”“修正来源信息”“跳过后保留 raw”“取消尚未开始的任务”。写入不确定时先提供“检查并恢复”，校验通过前不显示盲目重试。
- 保留现有导入、维护和 vault 接口路径；新增入库任务查询／取消、任务恢复、待处理汇总及来源元数据修正接口。手动入库与多 vault 追加改为返回 HTTP 202 和任务 ID，前端随后查询结果；这是本机 v1 响应结构的明确变更，需同步更新 Web 客户端、测试和 README，不能把 `queued` 误报为 `imported`。

## 验收场景

1. 新安装导入有效本地资料，立即得到接收记录，并自动进入默认 vault；旧安装的手动规则升级后保持不变。raw 成功后，只有开启自动维护的 vault 才排知识任务。
2. 连续推送两篇资料，第一篇 Claude 阶段超时：确认进程退出、第一篇延时重试，第二篇继续处理；全程最多一个来源 Claude CLI 进程。
3. CLI 缺失／未登录时任务保留、显示一条全局待处理；修复后继续。服务在分析或写入中重启，分别安全重排或检查 journal，不重复覆盖。
4. 同一本地文件或同一 Clipper 来源重复推送，虽然接收时间不同，仍复用同 vault 的已验证 raw 和维护结果；另一 vault 独立入库与维护。
5. Markdown frontmatter、HTML 作者元数据和明确 byline 分别能提取作者并显示依据；无依据或相互矛盾时不猜测。归属按导入规则默认值，单篇覆盖生效；URL 不被当作第三方的充分证据。
6. 用户更正已入库作者或归属，raw 哈希不变，manifest 与相关已编译笔记经受控校验保持一致；冲突或校验失败进入待处理。
7. `ask_user`、反复失败和写入待检查跨页面显示；未解决 24 小时后在下次打开应用时提醒。`defer` 和 `keep_raw_only` 不产生故障提醒。

## 实施拆分与风险

先补持久入库任务、超时退出确认、租约和恢复，再接稳定来源映射与作者提取，最后接待处理入口、隔日提醒和元数据修正。已知归属／作者的纠错依赖相邻 vault-maintainer 仓库新增受控 CLI 命令；实现前需核对该仓库的可写权限与版本兼容。现有工作区有大量未提交的其他改动，实施和提交时只纳入本设计对应文件，不清理或覆盖用户工作。
