# Open Context Forge 首版产品设计

日期：2026-10-22  
状态：已获产品方向确认；分阶段实施

## 1. 已确认的方向

- 面向个人桌面使用，首版提供本机运行、浏览器打开的**流程工作台**。独立原生桌面壳不属于首版。
- Markdown/Obsidian vault 是长期知识资产的主库。平台可以建立索引和任务状态，但不建立一套无法导出的平行知识库。
- 首版资料以文章、报告等非结构化内容为主；结构化数据计算与可视化后置。
- 智能体使用现有 CLI 或 API 能力与已有 skills。首轮以当前本机 Claude CLI 登录验证；可选择 Claude CLI + DeepSeek 或 Claude API Key 方案，配置后再启用。平台负责界面、业务状态、数据连接和审核，不开发新的通用智能体循环。
- DeepSeek Harness 暂不纳入首版；保留运行时接口，后续通过独立验证决定是否接入。
- 首条完整发布链路为 apframework 博客，第二条为微信公众号。每个渠道都先本地预览、人工定稿，再由用户在界面确认发布。
- 多知识库是首版能力：首次启动自动创建并选中一个内置默认 vault；用户也可登记已有的外部 Obsidian vault。资料可归入指定 vault，写作项目可读取多个已授权 vault 的证据。

## 2. 首版目标与边界

用户可以将 Clipper 导出的多篇文章导入一个分析批次，检查来源与质量，逐篇分析并形成跨资料证据，确认写入两个独立 vault；随后建立文章项目，反复与所选智能体讨论并修改正文，完成本地预览，发布至 apframework 博客，最终获得经验证的公开链接。

首版不包含团队协作、计费、云端知识库托管、公开插件市场、结构化数据分析、公众号自动群发，以及无人值守的自动发布。

## 3. 界面与交互

流程工作台采用左侧导航与页面工作区。导航设为：**资料与分析、文章工作台、预览与发布**；知识库和设置位于工作区入口。2026-10-24 确认移除全局智能体协作栏：资料页的 AI 是来源分析卡等有范围的任务，文章页在当前文章内部提供可收起的写作对话；知识库只读浏览，设置管理连接，预览与发布不显示通用对话。文章对话按文章 ID 保存，切换页面不会把上下文带入其他页面。

### 3.1 资料与分析

资料处理台以跨批次列表为主体。顶部只保留紧凑的 ZIP 导入入口与当前处理规则；后续浏览器插件复用采集入口。采集到平台与写入 vault 是两个动作：默认把资料放入“待整理”，也可在页面内设置自动直接入库的目标 vault。自动入库在本机服务后台执行，失败或不完整项仍可在待整理中处理。待整理不按日期截断；最近处理是最近 7 天的动态视图，时间到期不会删除资料；全部采集记录可持续查询。列表支持搜索、状态筛选、分页、批量入库、生成分析卡、搁置、回收站与明确确认后的永久删除。

资料与分析中的入库关系是单向追加的：一篇资料可以进入多个知识库，已入库的关联不能在此取消。回收站与永久删除只适用于未入库采集记录；已入库来源将来在知识库中统一处理文件、清单和索引的删除。

逐篇来源分析卡可在入库前或入库后生成，结果直接保存在平台中；资料页只显示“未分析／已分析”，可随时重新分析。分析卡不设人工确认步骤，也不是入库或文章写作的前置条件。知识库仍以来源快照和原有笔记为主要阅读内容；历史写入的分析文件保留。跨资料共同点、分歧与多资料提问后续作为资料页内的选中来源任务接入。每条结论须可回跳到来源快照的具体位置。知识笔记作为**提案**出现；用户确认后才写入 vault。

### 3.2 知识库

首次启动在应用数据目录自动初始化内置 vault，设为默认目标。用户可添加已有的外部 Obsidian vault；若该目录尚未采用 OCF 结构，界面先展示将创建的目录和文件，用户确认后再调用 vault-maintainer 的 adopt 流程。可登记多个本机 vault，并检查目录是否可读写、是否重复登记。导入时预选默认 vault，但目标始终可见且可切换；用户可更改默认 vault。界面能浏览来源、分析卡、知识笔记及其引用关系，显示每个文件的来源和最近更新时间。平台创建的文件遵守已有 vault-maintainer 的命名和结构约定。手工在 Obsidian 修改文件后，平台重新索引，不覆盖用户修改。

### 3.3 文章工作台

新建文章时选择一个或多个 vault、主题与目标读者。工作区展示证据清单、立场与大纲、Markdown 正文、渲染预览、版本记录。用户能选中段落向所选智能体提问；智能体给出带依据的建议和差异，用户逐条接受或拒绝。每个事实性主张能展开证据来源，缺证据、来源冲突和引用失效会被标出。

写作状态依次为：选题、证据整理、大纲、草稿、审稿、定稿。重新编辑已定稿版本时生成新版本，旧定稿及其发布记录保持可追溯。

### 3.4 预览与发布

定稿文章先在本机以渠道格式预览正文、图片、图注和引用。博客发布按“生成 MDX 与资源 → 本地构建与预览 → 用户确认 → 写入并提交博客仓库 → 部署 → 验证公开 URL”执行。`已写入仓库` 与 `已上线` 是不同状态；只有公开 URL 可访问且内容匹配定稿版本，才标记为已上线。

公众号作为第二阶段渠道，先沿用现有发布器的编辑器导入包，提供渠道预览、复制或导入检查与人工确认。平台不得把导入包生成视为公众号已发布；是否增加平台草稿接口或自动发布，须单独调研和设计。

## 4. 数据与组件边界

### 4.1 长期文件与运行状态

- 内置 vault 位于应用数据目录，外部 vault 保留在用户原有路径；两者采用相同的 OCF 文件结构。vault 保存来源快照和知识笔记；历史分析文件继续可读，新生成的资料分析卡先保存在平台记录中。来源快照保留原始 URL、抓取时间与内容指纹，不因再次分析而改写。
- 文章项目保存 Markdown 正文、证据清单、版本与渠道导出记录，使用可直接检查和备份的本机文件。文章可引用多个 vault 的证据，但不会把证据复制成失去来源的正文资料。
- 本地数据库只保存导入队列、任务进度、会话映射、搜索索引和界面状态；上述长期文件是可迁移的权威内容。
- 引用使用 `vault ID + 文件相对路径 + 内容指纹 + 定位信息`。源文件变化后，引用标为需复核，不静默更新论据。

### 4.2 服务边界

本机服务向流程工作台提供稳定接口，内部划分为：

1. **导入服务**：读取 Clipper ZIP，校验结构，去重，保存不可变来源。
2. **知识库服务**：管理多个 vault、索引、读取和经确认的写入。
3. **证据服务**：跨 vault 查询、来源定位、冲突提示和证据清单。
4. **文章服务**：项目、版本、建议差异、定稿与预览。
5. **智能体适配器**：把当前工作上下文及允许操作交给所选智能体，并把建议、引用和任务事件返回界面。业务状态由平台管理，不由对话文本推断。本机优先验证 Claude CLI；适配层保留 ACP 兼容边界，后续可接 Codex 或其他智能体，不依赖某一种 CLI 的会话格式。
6. **发布适配器**：调用现有博客发布能力，保存渠道包、构建结果、提交记录和公开 URL 的验证结果。

服务接口从首版就带工作区与资源标识。个人桌面版只有一个本地用户；未来 SaaS 在同一业务接口上增加账户、租户隔离、云存储、任务执行隔离和密钥管理。

## 5. 关键约束与失败处理

- 智能体对知识笔记、文章正文和发布目标的修改以提案或差异呈现；用户确认后写入。来源快照不可覆盖。
- 导入不完整或格式错误的资料仍可保留为待处理项，但不能进入“分析完成”。重复来源可查看、跳过或作为新版本导入。
- 所选智能体不可用时，已保存的来源、知识笔记与文章仍可浏览和人工编辑；分析与协作任务显示可恢复的失败状态。
- 单篇分析失败不会撤销批次中成功的其他资料。批次汇总明确列出未纳入的资料。
- 文章证据被修改或失效时，定稿状态失效，必须重新审稿和预览。
- 博客写入或部署失败时保留渠道包与失败原因，允许从相应阶段重试；不重复创建同一版本的文章。
- 发布操作在界面显示目标仓库、文章路径、版本与预计动作，用户明确确认后执行。

## 6. 验收与阶段

**首版完整验收路径**：首次启动自动出现内置默认 vault，并能添加一个外部 vault；从一份含多篇资料的 Clipper ZIP 开始，识别至少一项重复或不完整资料；将有效资料分别整理到两个 vault；在文章项目中引用两个 vault 的证据并可回查原文；至少两轮与所选智能体的段落讨论留下可接受或拒绝的修改记录；定稿后完成本地博客预览；发布至 apframework 并验证公开链接。

实施顺序采用纵向切片：先走通单篇资料到博客公开链接，再扩展为批量导入和双 vault 证据；之后完善错误恢复、版本和渠道预览，最后接入公众号导入包。首版验收要求完整的批量、双 vault 到博客链路。Web/SaaS 是后续产品阶段，不阻塞个人桌面版。

## 7. 可复用资产与待验证事项

- 复用现有 `open-context-clipper` ZIP 数据格式、`open-context-forge-vault-maintainer` 的来源与知识笔记约定、`open-context-forge-tech-article-writer` 的写作阶段和证据清单，以及 `open-context-forge-article-publisher` 的博客导出能力。
- 分阶段验证智能体适配器的长会话、事件流、任务取消、恢复和建议差异；若某项能力不足，只调整适配层，不改变文章与知识库的数据契约。首轮 Claude CLI 使用其非交互 JSON 输出和 session ID 续接，ACP 接入留待后续验证。
- 实现前用真实 Clipper ZIP 和现有 vault 样本检查格式兼容性；用 apframework 博客的本地构建与预览确认渠道导出结果。
- DeepSeek Harness 只保留为后续可选运行时验证项，不进入首版依赖、部署或用户设置。
