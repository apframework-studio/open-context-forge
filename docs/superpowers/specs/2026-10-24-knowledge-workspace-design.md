# 知识库独立工作区设计

日期：2026-10-24
状态：已确认（2026-10-24）

## 目标与边界

知识库是相对独立的阅读和探索工作区。用户进入后能立即看见刚保存的来源资料，也能按原有目录浏览已连接的 Obsidian vault 中的 Markdown 笔记，并通过搜索和图谱追溯关系。首版网页只读；原有笔记的编辑继续在 Obsidian 完成。平台不把 Markdown 内容迁入另一套不可导出的存储。

当前“保存到知识库”只产生 `raw/sources/` 中的来源快照；资料与分析中新生成的分析卡保存在平台记录中，不再要求确认写入 `.ocf/compilations/`。历史分析文件保留在库中；`wiki/` 中的知识笔记仍需单独编写或编译。页面必须区分“已保存来源”“平台分析卡”“库内分析文件”“已形成知识笔记”。

## 导航与页面

主导航把“知识库”作为独立工作区入口，与“资料与分析 → 文章工作台 → 预览与发布”的流程组区分。知识库内顶部提供 vault 选择器、跨库搜索入口，以及跳转“设置 → 知识库连接”的管理入口。主体分为三个页签；每个页签保留当前 vault 和筛选上下文。

### 概览

- 默认展示所有已连接 vault 的“刚入库来源”和“最近修改笔记”，每项注明所属 vault；可切换为单库概览。
- 单库概览显示库用途、来源数、笔记数、库内分析文件数、上次索引时间及读取异常。
- 若 vault profile 配置了人工维护的索引文件，渲染它作为导读；它与平台自动生成的文件索引是两个对象。接入的旧 vault 可能没有配置该文件，此时显示明确的空态。
- “刚入库”按 manifest 中的导入时间排序，“最近修改”按文件修改时间排序。时间窗口只影响快捷视图，不删除或隐藏完整内容。

### 浏览

- 左侧保留原有文件夹树，中间为可搜索的内容列表，详情区渲染 Markdown。窄屏改为逐层导航，不强塞三栏。
- 内容类型至少包括来源快照与原有 Markdown 笔记；历史库内分析文件可附在对应来源的详情中。资料页中新生成的分析卡不作为知识库浏览的前置条件。
- 资料与分析只允许向知识库追加来源归属。已入库来源的删除属于知识库工作区，未来须同时核对来源文件、manifest、分析卡及派生索引；当前只读浏览阶段不开放该删除动作。
- 搜索标题、路径和正文，显示命中片段；按 vault、内容类型、目录、修改时间和分析状态筛选。支持按最近入库、最近修改和标题排序。
- 来源详情展示原文、来源 URL、抓取／导入时间、归属、指纹和分析卡；笔记详情展示 Markdown、文件路径、出链、反向链接和引用的来源。提供“在 Obsidian 打开”及复制本机路径的入口，不在网页写回笔记。
- 没有 OCF frontmatter 的原有笔记仍正常索引和展示，标为普通笔记；仅缺少不能从文件中可靠取得的来源元数据。

### 图谱

- 首版图谱以单个 vault 为范围。默认节点为来源快照与 Markdown 笔记；分析卡在来源节点上以状态标记呈现，可按需展开为节点。
- 边只来自可核对的关系：笔记中的 `[[wikilinks]]`、相对 Markdown 链接、`source_snapshot`／`source_fingerprint` 元数据，以及可解析的来源行号引用。边可回跳到对应文件或证据位置。
- 支持平移、缩放、重置视野、按类型筛选、搜索定位、聚焦相邻节点、点击节点打开详情。孤立节点保留；失效或有歧义的链接列入可检查清单，不静默猜测目标。
- 不把主题相近或模型推测的关联直接画成事实边。跨 vault 图谱待稳定的跨库引用约定确定后再做。
- 大型 vault 默认只绘制当前筛选或焦点子图，避免一次渲染全部文件阻塞页面。

## 知识库连接设置

“设置 → 知识库连接”集中展示内置和外部 vault 的名称、类型、本机路径、默认入库标记、读写状态、内容数量和上次索引时间。支持连接已有目录、预览采用 OCF 结构将新增的文件、确认连接、设置默认库、重新索引以及断开连接。断开连接仅移除平台登记和派生索引，不删除原目录内容；内置默认库不提供删除操作。

“连接外部知识库”表示登记本机目录的真实路径，不是网页 URL、符号链接或整库复制。采用目录前仍展示文件变更预览。资料页继续显示当前自动保存规则和快捷修改入口；完整配置归入设置，不增加知识库浏览页的管理表单。

## 索引与数据安全

- Markdown 文件、vault profile 和来源 manifest 是长期内容的权威数据。SQLite 只保存可重建的检索、链接与界面索引。
- 读取 `vault.json` 指定的 wiki 与 sources 路径；普通笔记索引遵循原目录结构。profile 配置的 index 文件单独用于概览，配置的 log 文件与 `.ocf` 内部文件不作为普通笔记重复展示。外部 vault 的 wiki 路径可能是 `.`，索引时仍须排除来源目录和内部元数据。
- 首次连接或手动重扫建立全量索引；平台导入后更新相关索引；外部文件变化经防抖刷新。界面展示最近索引时间并始终提供手动重扫，以处理文件监视失效。
- 路径访问须限制在所连接 vault 的真实目录内，跳过符号链接；读取失败、文件被移走和哈希变化须显示为可恢复状态。只读浏览和索引不得改写原有 Markdown。
- 同名 wikilink 只有唯一目标时才连边；解析不到或有多个候选时显示问题，不任选一个。所有图谱节点和边都能追溯到 vault 相对路径。

## 实施切片与验收

1. **可浏览的知识库**：整理导航和设置入口，建立来源与原有笔记的统一索引，实现概览、目录浏览、全文搜索和只读详情。默认库的三篇现有来源应立即出现在“刚入库”与浏览列表；空的 `wiki/index.md` 不应被当成知识笔记。
2. **可信关系图谱**：在相同索引上解析可验证链接，提供图谱、反向链接、孤立节点和失效链接提示。连接一个带有原有 wikilink 的外部 vault 后，笔记和对应边应可见；没有真实关系的默认库可显示孤立来源。
3. **同步与恢复**：在 Obsidian 修改、添加或移走笔记后，自动或手动重扫可更新列表与图谱；断开外部库后其文件原样保留，重新连接可重建索引。

首版验收不包含网页内编辑原有 Markdown、自动生成未经确认的语义连线、跨库图谱或云端 vault 托管。知识笔记的生成与确认是后续独立工作流；它写入 vault 后自然进入上述索引和图谱。
